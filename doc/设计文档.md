# 医药大数据 Graph RAG 关联分析问答系统设计文档

## 1. 系统概述

### 1.1 系统背景与设计目标

传统医疗问答系统面临两大核心缺陷：普通关键词检索缺乏语义理解能力；标准向量检索（Naive RAG）受限于文本块切片粒度，无法完成跨文档的多跳逻辑推理（如药物相互作用、配伍禁忌推演）。

本系统旨在结合**多模态大数据计算引擎**与 **Graph RAG（知识图谱增强生成）**，实现以下目标：

1. **海量异构数据治理**：基于数仓架构（ODS-DWD-ADS）完成医药数据清洗、离线指标建模与高并发毫秒级点查。
2. **图谱拓扑挖掘**：利用 Spark GraphX 对药品-疾病-成分网络进行分布式图挖掘（PageRank、社区聚类），构建结构化医药知识图谱。
3. **Graph RAG 混合召回**：通过“向量相似度 + 图谱多跳路径 + 数仓统计指标”的三路混合召回，支撑具备深度推理能力且可溯源的临床医药辅助问答。
4. **企业级后端工程闭环**：基于 Java Spring Boot 构建高可用网关、流式协议（SSE）传输、高并发限流缓存与任务调度中枢。

## 3. 数据层与数仓建模设计

### 3.1 数仓分层架构（Hive / HDFS）

数仓采用标准分层架构，保障数据分析指标的离线聚合与统计：

- **ODS 层（原始数据层）**：存放未清洗的爬虫抓取数据，包括 `ods_drug_raw_json`、`ods_disease_raw_csv`、`ods_interaction_log`。
- **DWD 层（明细数据层）**：清洗特殊符号与脏数据，标准化实体标识，构建：
  - `dwd_drug_dimension`（药品维度表：批准文号、通用名、剂型、规格）。
  - `dwd_disease_symptom_fact`（病症关联事实表：疾病ID、关联症状ID、关联权重）。
  - `dwd_drug_interaction_fact`（用药相互作用事实表：药物A_ID、药物B_ID、严重级别、不良后果）。
- **ADS 层（应用数据层，支撑大屏分析）**：
  - `ads_department_disease_rank`：各科室高发疾病热度与季节性波动统计。
  - `ads_contraindication_frequency`：高风险配伍禁忌组合 Top 100 频次统计。
  - `ads_ingredient_overlap_matrix`：多药品间有效成分重叠与过量风险宽表。

### 3.2 多模态存储模型设计

**1. HBase（海量原始明细秒级点查）**

- **表名**：`medical_corpus:drug_detail`

- **RowKey 设计**：采用离散化与降序组合方案，避免热点倾斜：

  $$\text{RowKey} = \text{MD5}(\text{Category})[0:4] \text{ + } \text{DrugID} \text{ + } (9999999999999 - \text{Timestamp})$$

- **列族设计**：

  - 列族 `info`：`name`, `spec`, `usage`, `adverse_reaction`
  - 列族 `manual`：`contraindication_text`, `pharmacology_text`（全量说明书文本）

**2. Neo4j（核心图谱关系模式）**

- **节点标签**：`:Disease`、`:Drug`、`:Ingredient`、`:Symptom`
- **边类型及属性**：
  - `(:Drug)-[:CONTAINS {dose: String}]->(:Ingredient)`
  - `(:Drug)-[:TREATS {efficacy: Float}]->(:Disease)`
  - `(:Disease)-[:HAS_SYMPTOM {probability: Float}]->(:Symptom)`
  - `(:Drug)-[:INTERACTS_WITH {level: String, risk_detail: String}]->(:Drug)`

**3. MongoDB（文档切片与对话状态）**

- **集合 `chat_session`**：

  JSON

  ```
  {
    "_id": "ObjectId",
    "user_id": 10001,
    "session_id": "uuid-v4",
    "messages": [
      {
        "role": "user",
        "content": "高血压患者合并干咳，可以用卡托普利吗？",
        "created_at": 1773532800
      },
      {
        "role": "assistant",
        "content": "...",
        "retrieval_trace": {
          "entities": ["高血压", "干咳", "卡托普利"],
          "graph_paths": ["卡托普利 -> 常见不良反应 -> 干咳"],
          "doc_chunks": ["chunk_id_9824"]
        }
      }
    ]
  }
  ```

## 4. 核心功能模块详细设计

### 4.1 知识图谱构建与图挖掘分析模块

1. **实体与关系离线挖掘**：基于开源医药语料，利用 Spark SQL 清洗抽取结构化三元组，批量通过 Cypher 脚本导入 Neo4j 构建图拓扑底座。

2. **Spark GraphX 拓扑分析计算**：

   - **PageRank 节点重要度评估**：

     $$PR(u) = \frac{1-d}{N} + d \sum_{v \in B_u} \frac{PR(v)}{L(v)}$$

     识别临床网络中的基石药物与中枢病症节点，将重要性权重回写到 Neo4j 节点属性中，用于 RAG 检索时的路径跳步优先级排序。

   - **Louvain 社区划分**：对复杂的药物成分共现网络做社群聚类，挖掘潜在并用方案的隐式分组，为数仓提供聚类宽表。

### 4.2 Graph RAG 混合检索与推理流程

当用户输入问诊或咨询问题时，FastAPI 引擎执行如下处理链：

```
                    用户输入 Query
                         │
                         ▼
             [意图解析与医学实体识别 (NER)]
                         │
         ┌───────────────┼───────────────┐
         ▼               ▼               ▼
   [向量相似度检索]   [图谱拓扑路径检索]   [数仓指标直查]
   (Milvus 稠密向量)  (Neo4j 1~2跳子图)   (HBase 禁忌明细)
         │               │               │
         └───────────────┼───────────────┘
                         ▼
             [跨模态重排序与剪枝 (Rerank)]
                         │
                         ▼
             [结构化 Prompt 模板装配]
                         │
                         ▼
             [LLM 流式推理与路径归因生成]
```

1. **实体解析与意图识别**：

   - 利用微调的模型或专用医学分词词典提取问句中的关键实体集合 $E = \{e_1, e_2, \dots, e_n\}$（如：疾病名、药物通用名、症状）。

2. **三路并行检索**：

   - **Path 1（语义检索）**：生成 Query 向量并在 Milvus 中进行 Cosine 检索，召回 Top-K 临床指南与学术文献切片（Chunk）。

   - **Path 2（图谱多跳检索）**：针对实体集合 $E$，在 Neo4j 中执行 Cypher 检索 $1 \sim 2$ 跳邻域：

     Cypher

     ```
     MATCH path = (d:Drug)-[r:INTERACTS_WITH|CONTAINS|TREATS]-(target)
     WHERE d.name IN $entity_list
     RETURN path LIMIT 50;
     ```

     检索药物之间的配伍禁忌边，或“药物 $\rightarrow$ 成分 $\rightarrow$ 禁忌病症”的间接推导链条。

   - **Path 3（数仓宽表核验）**：若判定涉及双药/多药并用，直连 HBase 读取结构化配伍禁忌矩阵，提取硬性规则阻断数据。

3. **Prompt 上下文装配与模型推理**：

   - 采用 Rerank 模型对图谱路径三元组与文本 Chunk 按照相关度重排，过滤无效噪音。
   - 构建带有约束规则的 Prompt（要求模型必须优先遵从检索到的知识图谱事实链，并在回答中引用实体关系节点），调用大模型流式输出解答。

### 4.3 Java 后端业务与工程化调度设计

Spring Boot 负责全生命周期安全、流量治理与异步编排：

1. **SSE 流式传输控制**：
   - 前端使用 `EventSource` 订阅后，Spring Boot Controller 创建 `SseEmitter` 实例。
   - 建立与 Python FastAPI 流式端点的 HTTP/2 长连接客户端，逐帧分发两类自定义事件：
     - `event: trace`：传输检索到的图谱推理路径数据（用于前端 3D 拓扑节点点亮）。
     - `event: token`：传输大语言模型生成的流式回答文本。
2. **限流与高可用方案**：
   - 集成 Redis Lua 脚本实现滑动窗口限流器，对非白名单用户限制请求频次（如 20 次/分钟），防范爬虫与恶意爆破。
   - 对相同 Query 提取特征 Hash，建立 10 分钟短时本地 Caffeine + 分布式 Redis 二级缓存，降低底层大模型调用负荷。
3. **分布式任务调度（XXL-Job）**：
   - 注册 `DrugWarehouseSyncJob`：每周日凌晨触发 Spark 离线增量数据清洗与 ADS 聚合计算。
   - 注册 `GraphIndexRefreshJob`：根据新增药品文档，触发增量图谱实体写入与 Milvus 向量重索引。

## 5. 核心接口规范设计

### 5.1 流式智能问答接口

- **Endpoint**：`GET /api/v1/chat/stream`

- **协议**：Server-Sent Events (SSE)

- **入参格式（Query Param）**：

  - `sessionId` (String)：会话全局唯一 UUID。
  - `query` (String)：用户问询文本。

- **数据帧返回示例**：

  ```
  event: trace
  data: {"entities":["卡托普利","二甲双胍"],"graph_edges":[{"from":"卡托普利","to":"干咳","rel":"常见副作用"},{"from":"卡托普利","to":"二甲双胍","rel":"无显著相互作用"}]}
  
  event: token
  data: {"delta": "针对"}
  
  event: token
  data: {"delta": "高血压合并糖尿病患者..."}
  
  event: done
  data: {"status": "success", "total_tokens": 348}
  ```

- **Endpoint**：`GET /api/v1/dashboard/metrics`

- **协议**：HTTP RESTful

- **返回格式（JSON）**：
